# WiFi Voucher — Production Hardening Audit

## What was fixed
- Blocked SSRF through router host input by DNS-resolving targets and rejecting private/local/CGNAT/link-local/multicast addresses by default.
- Added RouterOS secure API/TLS support (recommended port 8729); legacy plaintext API remains explicitly supported for existing routers.
- Added per-route rate limits to expensive router operations.
- Restricted CORS to the configured APP_URL instead of allowing arbitrary origins with credentials.
- Removed environment-specific Supabase URL/anon-key configuration from the committed frontend; /config.js is generated by the backend.
- Pinned the browser Supabase SDK version instead of loading a floating major version.
- Ensured encrypted router credentials are never returned by the router creation API.
- Moved router connection-health writes to the service-role backend after database grants were hardened.
- Hardened Supabase RLS checks for profiles, vouchers, and generation logs.
- Prevented browser users from changing subscription state, role, router credentials, router ownership, or router health state through direct Supabase access.
- Added atomic Mobile Money subscription renewal to avoid concurrent-payment lost updates.
- Added size validation to the Mobile Money webhook payload.
- Added CSV escaping and spreadsheet-formula injection protection to voucher exports.
- Added router cleanup/compensation when a voucher database save fails after RouterOS users were created.
- Added safe router deletion: voucher users are cleaned from RouterOS before the database router record is deleted.
- Added production environment validation and sanitized production 5xx responses.
- Added network-security tests.
- Removed unused @fastify/jwt dependency.

## Verification performed
- JavaScript/CJS syntax check: passed for all source files.
- Automated tests: 16 passed, 0 failed.
- Static security smell scan: no remaining arbitrary-CORS configuration, hardcoded service-role frontend exposure, or floating Supabase CDN version.

## Important limitation
This environment could not download npm dependencies from the npm registry, so a full Fastify/Supabase integration boot test and npm audit could not be run here. The existing dependency tree should therefore be installed and tested in CI/Render before the first paying customer.

The real MikroTik integration also still needs to be exercised against the customer's actual RouterOS device, because network reachability, RouterOS API permissions, TLS certificates, ISP port forwarding, and CGNAT are environmental conditions that cannot be simulated reliably from this source-only audit.
